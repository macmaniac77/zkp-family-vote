Key creation & storage

Your secret key is the only thing that can prove you are an eligible voter. The server is designed to never receive it — only your public key (at registration) and later a ring signature (at vote time).

Offline hash signing

When you vote offline, the browser hashes the ballot message vote|electionId|choice|keyImage into a message hash, then builds a linkable ring signature over it. You export a ballot package that contains only the signature + hashes — not sk. Upload that package later from any online device.

1 · Choose a creation method

🎲
Random (recommended)

CSPRNG → 32 bytes → secp256k1 scalar. Highest entropy. If you lose the backup, the key is gone forever.

🔑
Passphrase-derived

PBKDF2-HMAC-SHA-256 with 210,000 iterations stretches your passphrase with a random salt. Same passphrase + salt always yields the same secret. Store the salt with the backup (it is public).

📥
Import

Paste secret hex from a paper wallet or JSON backup. Public key is recomputed locally for a sanity check.

2 · Choose how to store it

⏱
Session only

Nothing written to disk. Closing the tab forgets the key. Best on a shared PC after you already exported a backup.

No action needed — key stays in page memory until reload.

🔒
Encrypted vault (recommended)

AES-256-GCM. Unlock passphrase is independent of a passphrase-derived voting key. Only ciphertext is stored in localStorage.

⚠
Browser plaintext

Convenient on a personal laptop. Any browser extension or local malware can read it. Clear after the election.

📄
File / paper

Download a human-readable paper wallet or a raw JSON identity (contains the secret — treat like cash).
